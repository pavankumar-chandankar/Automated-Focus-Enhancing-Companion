# v0.11 — semantic screen awareness preview

## How to use
1. Keep Groq on the Free plan and Ollama stopped. Start a focus session with a specific goal (e.g. "I need to work on my robotics thesis").
2. Say "Watch my screen". Click Choose work window. macOS may ask for Screen & System Audio Recording permission; grant only if desired. Relaunch the app if macOS requires it. No audio is captured.
3. Pick one window from the local list and click Watch this window. This first preview supports a small allowlist of common browsers, Word, Pages, Preview, TextEdit, VS Code, Obsidian and Notes. Terminal, messaging, mail, system settings, password managers and unknown apps are excluded. This does NOT guarantee that an allowed browser or document lacks sensitive content.
4. Close the conversation bubble and bring the chosen window to the foreground. While the character is compact, a screenshot attempt occurs at most every 15 seconds. The selected ID, owner process and bundle must match and the selected window must be the top normal window of the active app. Switching to another window produces no capture. A fresh OCR excerpt produces Screen · read; otherwise Screen · local. That is not a measure of attention.
5. Click the character and say "What can you read?" to review the latest locally recognized text (up to 600 characters) and the actual declared goal. It expires in at most 60 seconds. No text is automatically sent. Choose Don't share or Analyze with Groq once. If approved, only those displayed text fields are sent to the configured Groq model, with a separate bounded relevance prompt. The model may suggest a neutral question but cannot propose or execute a session action from OCR.
6. Say "Stop watching my screen", "Stop watching", "Don't interrupt me", or choose menu-bar Stop screen observation. Pause, finish, new session, hide and quit revoke observation. Resuming requires a new selection. The OS permission can remain granted; the app's consent is separate and starts off each time.

## Technical boundary
The Objective-C bridge calls ScreenCaptureKit SCScreenshotManager (macOS 14+) with a selected-window filter and bounded resolution (long edge at most 1440 pixels); Apple Vision fast OCR runs locally, English/German initial languages. No screen pixels or text written to disk, no audio, no raw screenshot network transfer, no automatic cloud observation calls. The latest text and window metadata are held in process RAM only. After one minute an excerpt is no longer available for review or analysis; inaccessible stale text may remain in RAM until the next sample, preview attempt or revocation. Stopping clears state and invalidates results from in-flight workers; an already initiated one-shot OS capture or network request cannot necessarily be cancelled. No continuous screen stream. If permissions or capture fail, observation stops. The window list is local, including titles for selection. Cloud analysis bypasses ordinary conversation history, and its reply is not appended to chat memory. Ordinary chat does not receive OCR. Cloud retention is governed by Groq; don't send private information. Manual review is not an automatic redaction system.
The daily screen-analysis budget persists only day/count/time in screen-budget.json; at most 20 attempts per UTC day and one per minute. Failures count, no auto retry, Groq HTTP 429 shares the existing process cooldown. This cap is additional to provider token/request limits, not a guarantee of available quota or account tier. Existing chat and other apps may exhaust provider quota. No fallback to paid DeepSeek. Do not upgrade Groq.
macOS bridge builds with Xcode clang and the cc Rust build dependency. Windows retains the unsupported stub. No new local model download, paid service or separate helper process.

## Acceptance checks
- Build on M1; verify existing dialogue and activity awareness. Check that selecting no window or denying permission does not capture.
- Use a non-sensitive test document with a unique sentence. Select its window, fold the bubble and wait 15–30 seconds. Verify the readback contains the test sentence, not a hallucination. Check a different window and ensure no new text is captured; old text expires. Check that moving, hiding, pausing and restoring do not leak old observations.
- Verify Groq console shows no new requests during local sampling/readback. Review the exact excerpt and approve once; one cloud request should appear. Verify response relates to the stated goal and does not change session state. Verify cancellation, expired review and budget limits.
- Inspect Activity Monitor CPU/memory and Energy Impact before/after enabling. OCR accuracy and real overhead unmeasured. At this stage no proactive semantic interruption or automatic cloud relevance evaluation; next iteration should use measured capture quality and conservative event-driven filtering before such automation.

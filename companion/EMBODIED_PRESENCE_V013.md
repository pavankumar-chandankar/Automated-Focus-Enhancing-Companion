# v0.13 — embodied presence

The character is no longer a persistent dialogue reaction. Its local presence policy arbitrates existing UI and session events with explicit priorities: dragging, touch, transient gesture, processing, passive reminder, temporary reply reaction, open chat, local hover, autonomous pose, then base session pose. No inference of user emotions, new screen access, system-wide pointer tracking, audio, or model calls. The body, gaze, ears, arms, book and expression use procedural SVG/CSS. Mouse coordinates are used only within the character button, not stored. Press, drag and release do not alter native input/activation, geometry, bin, session state or chat history.

Idle: breathe, blink, occasionally stretch or look around after 12–29 seconds. Running: read a book, sparse page turns after 35–60 seconds (65–90 in quiet mode). Paused: rest and occasional yawn. These are animation choices based on explicit session state, not inferred user inactivity. A chat request shows thinking while pending; reply reactions expire in 1.6–2.4 seconds. A native check-in takes precedence over idle gestures. Completing an active session celebrates briefly. CSS reduced motion is respected. One cancellable autonomous timer, no per-frame JS, no extra IPC polling or cloud traffic. Hidden webview animations pause and destruction cleans timers.

Acceptance: with network disconnected, watch an idle companion for 35 seconds; verify spontaneous gesture and breathing. Hover, move pointer inside character, click, drag, release, fold and check responsiveness. Start a deterministic focus session and observe book/page turn, then pause and finish. Reconnect for Groq conversation; observe thinking and expiry of the reaction. Verify passive reminders, unsent drafts, native focus handling and separate analytics remain as before. Check Activity Monitor and reduced-motion setting. Existing screen recognition/classification accuracy, old session persistence and monitoring quality are not changed by this patch. Native behavior and animation quality need actual Mac testing; the pure policy tests do not establish native rendering or energy use.
